# Security policy

## Reporting a vulnerability

Report vulnerabilities privately through GitHub: private vulnerability reporting is enabled on this repository, so on its Security tab choose "Report a vulnerability". Please do not open a public issue for a security problem.

Include the version or image digest, what an attacker can do, and the steps to reproduce. The discussion stays in the private advisory. A fix goes into `main` and the next release, and the advisory is published once that release is out.

Vulnerabilities in the upstream daemons (ipp-usb, PAPPL and the printer applications, AirSane, Avahi, CUPS, SANE, HPLIP) belong to their projects. If printscan's configuration or packaging makes one of them worse, report it here too.

## Supported versions

Fixes go into the latest release and the `main` branch. Older releases do not get fixes; upgrade to the latest release.

## Threat model

printscan exposes a printer and a scanner on a home or small-office LAN. These are the boundaries it relies on:

- Web UI and API (port 8080): There is no login. The UI expects an authenticating reverse proxy in front of it and the ingress as its only route. Anyone who reaches port 8080 can print, scan, read scans and change the config. State-changing requests from other origins are refused, and pages are served with a strict Content-Security-Policy and same-origin opener and resource policies. API responses and scan downloads are not cached (`Cache-Control: no-store`).
- Allowed hosts: `PRINTSCAN_ALLOWED_HOSTS` (`--allowed-hosts`) lists the host names the UI and API answer to. Any other `Host` header gets 421 (`misdirected-request`), so a DNS-rebinding page in a LAN browser cannot reach the API. With the sim backend the default is `localhost,127.0.0.1,[::1]`. With the docker backend it is those names plus the host's IP address, read once at start (`--host-ip`, else the default route's source address). On Kubernetes the default is no check, because the ingress host is not known; set it to your ingress host name. `*` turns the check off. `/healthz` and `/readyz` are exempt.
- Proxy secret: when `PRINTSCAN_PROXY_SECRET` or `--proxy-secret-file` is set, every `/api/` request must carry that secret in `X-Printscan-Proxy-Secret` (or the header named by `--proxy-secret-header`), compared in constant time. Without it the API answers 401 (`unauthorized`). Configure your proxy to add the header, and the API stays closed if the forward-auth step is missing or bypassed. The secret is never a flag value, so it does not show up in the process list.
- Agent endpoint (port 8081): it accepts reports only with the bearer token from the `printscan-agent-token` Secret, compared in constant time. The token travels over plain HTTP inside the cluster: anyone who can capture traffic between the node and the control-plane pod can read it and send false device reports. Keep port 8081 off the ingress; the example NetworkPolicy allows it only from the node addresses the agent's traffic comes from, and its node CIDR is a placeholder you must set. With the docker backend the token is the file `<data-dir>/agent-token` (0600, created when the first config is applied and kept across restarts), seeded into a volume that only the agent container mounts, read-only. `compose.docker.yaml` binds port 8081 to 127.0.0.1, and the agent reaches it over the host's loopback interface; the flag's own default is still `:8081`. The sim backend opens no agent port.
- Device pod on the LAN: It uses the host network, so the node's LAN address carries mDNS, IPP (ipp-usb, the printer application, `ippeveprinter`) and eSCL (ipp-usb, AirSane). Anyone on the LAN can print and scan, as with a network printer. ipp-usb also proxies the printer's own web console, and AirSane's web page on port 8090 can start scans; both answer any LAN client, so a web page open in a LAN browser can send requests to them as well. ipp-usb listens on all of the node's interfaces. Avahi has wide-area DNS-SD turned off, so it publishes only on the local link. `allow-interfaces` is not set in `images/device/avahi-daemon.conf`, so Avahi announces on every interface of the node; setting it means rebuilding the device image. To keep these services off an interface, such as a VPN or a second network, run the device pod on a node that has only the LAN interface, or block the ports on the other interfaces with the node's firewall. PAPPL's admin pages refuse remote clients. printscan's own code opens no listening port in the device pod: the agent dials out.
- Kubernetes permissions: The control plane's Role is limited to its namespace, and every rule names its objects. It may read its own Deployment (`printscan`) and update its finalizers, read, create, patch and delete the device Deployment and ConfigMap (`printscan-device`), and read, create and patch the agent token Secret (`printscan-agent-token`). Device pods have generated names, so the Role allows `list` and `delete` on pods in the namespace. It cannot touch other namespaces or cluster-wide objects. The namespace needs the `privileged` Pod Security level only because the device pod uses the host network; the pod mounts no host paths and runs no privileged container. `deploy/examples/admission-policy.yaml` is a ValidatingAdmissionPolicy for the namespace that allows the host network and refuses privileged containers, `hostPath` volumes, `hostPID`, `hostIPC`, added capabilities and privilege escalation, so a stolen control-plane token cannot start a privileged pod there. Apply it alongside `deploy/base`.
- Docker Engine access (docker backend): the control plane talks to the Docker Engine API, through the mounted socket or `DOCKER_HOST`. That access is root-equivalent on the host: anyone who takes over the control plane can start a privileged container. printscan only stops or removes containers and volumes labelled `dev.printscan.managed-by=printscan`. A container or volume without that label that holds one of its names fails the rollout and is left alone. The calls it makes are `GET /_ping`; `GET /containers/json`, `GET /containers/{id}/json`, `POST /containers/create`, `POST /containers/{id}/start`, `POST /containers/{id}/stop`, `POST /containers/{id}/wait`, `DELETE /containers/{id}`, `PUT /containers/{id}/archive`; `GET /images/{name}/json`, `POST /images/create`; `GET /volumes/{name}`, `POST /volumes/create`, `DELETE /volumes/{name}`. A socket proxy can limit the control plane to these endpoints (README, "Socket proxy"), but creating containers stays root-equivalent, and a proxy on `127.0.0.1` is reachable by every local user. The device containers it creates use the host network and are never privileged.
- Containers: Every container drops all capabilities and runs with a read-only root file system and no privilege escalation. Containers that open the USB device node run as uid 0, because the device plugin creates device nodes owned by root. All others run as non-root users. With the docker backend, containers that write a shared named volume also run as uid 0, still with every capability dropped, because Docker has no fsGroup and a new volume belongs to root: the probe, fetch-blobs, and in probe and usb modes the agent, which stages vendor archives on the blob volume. Device containers there set `UsernsMode: host`, so they see the host's USB devices on a daemon with `userns-remap`.
- Never shelling out: printscan's Go code never starts processes. It talks IPP, eSCL, D-Bus, the Kubernetes API and the Docker Engine API, and a lint rule enforces this.
- Vendor files: printscan downloads proprietary files (today only HP's plug-in) only from the URL in the embedded catalog, with a size limit. It downloads the archive before acceptance, to show the licence text inside it, and installs it only after the licence is accepted in the config with the sha256 of that text. Each download must match both the vendor's OpenPGP signature, checked against a public key committed to this repository, and the sha256 pinned in the catalog. A staged archive is checked again before it is used. Archives are unpacked without following paths outside the target directory. They land on a separate volume that the driver containers mount read-only.
- Resource limits: request bodies have read deadlines (30 s for config and scan requests, 10 min for a print upload). A print upload is limited by `print.maxUploadMiB` and spooled to disk, not memory. Image conversion runs one PNG at a time and refuses a PNG whose decoded pixels would exceed 128 MiB (413 `image-too-large`), and the control plane sets its Go memory limit to 80% of its container's memory limit, read from the cgroup (`compose.docker.yaml` sets no memory limit). A CMYK JPEG is refused (415). printscan follows at most 32 submitted print jobs at once (429 `too-many-jobs`), and reads at most 8 MiB from an IPP response. A scanned page may be at most 256 MiB, and stored scans at most 1 GiB in total; new scans are then refused with 507 (`storage-full`).
- Config file: parsing is strict. Unknown keys and invalid values are rejected with their position, and an invalid file never replaces the running config. Writes are atomic and guarded by an ETag.
- Supply chain: Images are built in CI with SBOM and provenance attestations. Every base image is pinned by digest, every GitHub Action by commit SHA, and every upstream project built from source by commit SHA. The tool versions are locked in `mise.lock`. Renovate proposes updates, but updates to GitHub Actions, base images and upstream sources need a review and are never merged automatically.

Known limits:

- An attacker on the LAN can use the printer and scanner, and reach the printer's web console through ipp-usb. Restrict these ports on the node if the LAN is not trusted.
- An attacker who can read cluster traffic can read the agent token.
- With the docker backend, the Engine socket the control plane holds is root-equivalent on the host. A socket proxy on 127.0.0.1 narrows the API but is reachable by every local user, so on a multi-user host it is no safer than the socket.
- HP signs its plug-in with a 1024-bit DSA key over SHA-1. printscan checks that signature because it is the only one HP publishes.
